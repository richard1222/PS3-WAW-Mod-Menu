## 2. How they were built

### Tools (era: 2009–2014)

| Tool | Author | Role |
|---|---|---|

| **CoD5 / PS3 FastFile Editor** | BuC-ShoTz | PS3 support for WaW (also CoD4/MW2/BO). Trial version released; lineage continues in CoD-FF-Tools, which credits BuC-ShoTz and aerosoul94. |
| **CraigChrist's PS3 FF Viewer work** | CraigChrist (Se7enSins) | Attempted PS3 support for FF Viewer in the MW2 era. |
| **Official Treyarch CoD5 Mod Tools** (Mod Builder / Linker) | Treyarch | **PC only.** Raw files + zone CSV → linker.exe → .ff. Not usable for console patches. |
| **Correys CoD5 Tool** | Correy | Savegame .cfg injection (no-jailbreak USB route). |

ZoneBuilder is a Black Ops 1 tool — irrelevant to WaW.

### Period workflow (PS3)
1. Take a clean PS3 patch_mp.ff (or an "empty patch").
2. Open in the PS3-capable editor, extract the GSC rawfiles.
3. Edit plaintext in Notepad++ (later: GSC Studio).
4. **Update the 4-byte BE size field above each edited GSC** (the known PS3 pain point), recompress the zone.
5. Alternative route: edit the Xbox 360 patch in FF Viewer, then convert Xbox 360 → PS3.
6. FTP to `/dev_hdd0/game/<TITLE_ID>/USRDIR/english/`, overwrite, boot.

### PC vs PS3 patch_mp.ff
| | PS3 | PC |
|---|---|---|
| Magic | `IWffu100` (unsigned) | `IWffu100` |
| Version bytes | `00 00 01 83` (big-endian) | `83 01 00 00` (little-endian) |
| Compression | 64 KB blocks, 2-byte BE length prefix, `00 01` end marker | Single zlib stream, no blocks |
| Scripts | Plaintext, compiled at load | Plaintext, compiled at load |
| Distribution | Injected into patch_mp.ff in the update dir | Mods folder (`%AppData%/Activision/CoDWaW/mods`) + official Linker |

GSC source itself is platform-independent — the same .gsc works on both once packed correctly.

## 3. Game update compatibility

- **Required: game update 1.07** (confirmed via Karoolus tutorial). Modded patches live in the 1.07 title-update install directory and are loaded in preference to the disc.
- No evidence that different menus need different updates — they all target the same patch zone.
- **Title IDs:**
  - BLUS30192 (US)
  - BLES00354 (EU main), plus BLES00355 / BLES00357 / BLES00404 / BLES00457 (other EU regions)
  - BLKS20098 (JP)
- The patch must go in the folder matching the disc/update region: `/dev_hdd0/game/<TITLE_ID>/USRDIR/english/patch_mp.ff`.

## 4. Firmware compatibility

- **Firmware-agnostic.** Patches work on any CFW (3.55 through 4.9x), on HEN, and on DEX — they only need FTP/write access to `/dev_hdd0/game/<TITLE_ID>/USRDIR/english/`. No firmware-specific issues documented. (Note: a modern 2025 menu — Rowey 2025 — explicitly supports both HEN and CFW.)
- Requirement is write access, not jailbreak type: stock OFW without HEN cannot install one.
- Region matters; firmware does not.

## 5. patch_mp.ff technical reference

### Header (12 bytes)
- Offset 0x00, 8 bytes: magic `"IWffu100"` (hex `49 57 66 66 75 31 30 30`) — **unsigned**. The signed `IWff0100` magic is Xbox 360 MP only; PS3 patches are never RSA-signed, which is why unsigned modded patches load.
- Offset 0x08, 4 bytes: version `0x183` (387), **big-endian** (`00 00 01 83`).

### Compression
- Zone data split into **64 KB (0x10000) blocks**, each zlib deflate.
- Each block: `[2-byte BE compressed length][compressed data]`; the 2-byte zlib header is stripped from each block; the 4-byte Adler-32 checksum is retained. Stream ends with `00 01`.
- No custom crypto — just chunked raw-deflate.

### Zone structure (decompressed)
```
[52 bytes]  Zone header  (XFile 36B + XAssetList 16B)
[N bytes]   Asset table  (8 bytes per entry)
[N bytes]   Raw files section
[N bytes]   Localized strings (optional)
[N bytes]   Footer (zone name)
[pad]       Null padding to 64 KB boundary
```
- `ZoneSize` (0x00): total data size.
- `BlockSizeTemp` (0x08): **must be `0x10B0` for WaW** — engine uses it for memory allocation; wrong value = crash/hang.
- `BlockSizeVertex` (0x20): `0x5F8F0` for WaW.
- `AssetCount` (0x2C): **must include a mandatory +1 final rawfile entry** — missing it = infinite hang.
- Asset table entries (8 bytes): `[00 00 00][1-byte type ID][FF FF FF FF]`. WaW type IDs: rawfile = `0x22` (34), localize = `0x19` (25).

### How GSC scripts are stored — the critical fact
Each rawfile entry:
```
[FF FF FF FF]            marker
[4-byte BE size]         data size  <- must be updated when editing the file
[FF FF FF FF]            marker
filename (null-terminated)  e.g. "maps/mp/gametypes/_rank.gsc"
file data
[00]                     null terminator
```
**GSC is stored as PLAINTEXT source, not bytecode.** The game's own script compiler compiles it at load time. That's why 2009-era modders could edit menu text directly in FF Viewer — and why a GSC syntax error only surfaces as a load failure (there is no offline T4 script compiler).

### Loading behavior
- Loaded **at boot** as part of the fixed zone chain (code_pre_gfx → code_post_gfx → common → localized → patch). Later zones override same-named assets from earlier ones — so a script in patch_mp.ff with the same path as one in common.ff wins. The menu is live at the MP lobby; no map load needed.
- Typical mod-menu patches override `maps/mp/gametypes/_rank.gsc` (hooked to start the menu), `maps/mp/_utility.gsc`, `maps/mp/gametypes/_hud_util.gsc`, plus custom `*.gsc` menu files and localized strings.
- Typical sizes: retail patch ~213 KB; modded menu patches ~300 KB – ~1 MB.
- **Corrupt patch on PS3 = black-screen/hang during boot loading** (no graceful error). Rule #1: keep a backup of the original on the PS3 for one-FTP restore. `patch.ff` is the SP/co-op equivalent zone.

### GSC scripting for WaW
- C-like, `#include`-based; `self` = player entity, `level` = global. Core idiom: threads + events (`level thread onPlayerConnect();` → `level waittill("connected", player);` → per-player `onPlayerSpawned();` → `self waittill("spawned_player");`). Dynamic dispatch: `self thread [[ menu[cycle].function[scroll] ]]();`
- Classic bases (Karoolus → M40A3Fusionz → xRaW v3/v4/v5) share one architecture: hook line in a stock script (`maps/mp/gametypes/_rank.gsc`: `level thread <menu>::init();`), button-monitor thread mapping controller buttons to notify events, menu data in parallel arrays (`menu[cycle].name/function/input`), `drawMenu()` via `createFontString`/`setPoint`, cheats via `giveWeapon`, `setDvar`, god-mode tricks.
- **Color codes:** `^0` black, `^1` red, `^2` green, `^3` yellow, `^4` dark blue, `^5` light blue, `^6` pink, `^7` white, `^8` gray, `^9` brown.
- Reference: UGX Scripting Reference (https://wiki.ugx-mods.com), modsonline.com tutorials.

## 6. Can we compile one? — Feasibility

### Verdict: YES — and no compiler is needed
Because GSC ships as **plaintext compiled by the game at load**, "compiling a menu" is really **packing**: .gsc text → rawfiles in a valid PS3 zone → recompress.

### The tool: primetime43/CoD-FF-Tools
- https://github.com/primetime43/CoD-FF-Tools — GPL-3.0, actively maintained 2024–2026.
- WaW-on-PS3 rated **Full**: decompress → edit GSC/localize/weapon → recompress.
- FastFile Editor (GUI), **FastFile Compiler** (build new .ff from raw files; PS3/Xbox360/PC/Wii dropdown), PS3↔Xbox converter, Extractor, `ffcli`. Needs .NET 8.0; prebuilt releases on GitHub.
- Format docs in-repo: `docs/ZoneFileFormat.md`; companion repo `primetime43/cod-research` → `World-at-War-COD5/FastFiles/FastFiles.md`.
- Old forum-attachment tools are obsolete — this supersedes them.

### Practical path (with .gsc sources)
1. Windows PC + .NET 8.0; clean PS3 WaW `patch_mp.ff` (from the 1.07 update for your title ID); CFW/HEN PS3 with FTP.
2. Open clean patch in CoD FastFile Editor → extract rawfiles to inspect stock scripts and paths.
3. Edit .gsc sources (rename/rebrand text, credits).
4. Add menu .gsc files as rawfiles + hook line (e.g. in `_rank.gsc` or `maps/mp/_load.gsc`) so `init()` runs.
5. Rebuild the zone (editor recalculates sizes, AssetCount+1, 64 KB padding) → save as PS3 patch_mp.ff.
6. Back up original on PS3 → FTP new file over → boot WaW → MP lobby → test.
7. Iterate: GSC syntax error = boot hang; fix and re-push.

### ParadiseWAW correction
`canceer/paradisewaw` (fork of `gopro2027/ParadiseWAW`) is a **C++ SPRX plugin** (native code + plugin loader), **NOT** a patch_mp.ff/GSC project. It cannot be compiled into a patch_mp.ff — different approach entirely.

### Open-source GSC bases available
- **ineedbots/t4_bot_warfare** (https://github.com/ineedbots/t4_bot_warfare) — WaW GSC, maintained (Sep 2025); best open reference for correct WaW-era GSC idiom (not a menu).
- A 2022 trickshot-oriented GSC WaW mod menu exists on GitHub (Plutonium-targeted) — readable modern menu-base reference.
- **P!X V1 Menu Base** (CabConModding) — documents the `_rank.gsc` hook pattern.
- Historical bases (xRaW v5 / Ryan.gsc, M40A3Fusionz, Karoolus) survive only as dead MediaFire links / NGU login walls — why Richard's project is on hold pending his source upload.

### Blockers & risks
1. Source availability — the base must come from Richard (on hold until he uploads).
2. No offline T4 GSC syntax checker — errors surface only as boot hang on hardware. Change little, test often; keep the stock patch as a one-FTP restore.
3. Verify asset preservation before rebuild (retail patch is rawfile+localize; should be fine).
4. Hardware test loop mandatory.
5. Installation needs CFW/HEN write access to `/dev_hdd0/game/<TITLE_ID>/`.
6. Patch must match the console's title ID/region.

**Bottom line:** once Richard uploads the .gsc sources, the work is rebrand-the-text → pack with CoD-FF-Tools → FTP → test. No toolchain archaeology needed. Source quality is the only real unknown.

## SPRX Menus, Plugins & RTM Tools for WaW (PS3)

WaW on PS3 is overwhelmingly a **patch_mp.ff (GSC script)** scene — but SPRX plugins, RTM tools, and native-code menus exist too. This section covers everything SPRX-related for WaW.

> **Why patch_mp.ff dominates WaW:** unlike MW3 (where the PS3 `patch_mp.ff` is RSA-signed), WaW's PS3 patch uses the **unsigned** `IWffu100` magic. The game happily loads unsigned GSC scripts, so the simple "edit text → repack → FTP" workflow covers 99% of use cases. SPRX only matters when you need things GSC *can't* do: aimbots, ESP/wallhacks, memory-level anti-cheat, and off-host/non-host features.

### How SPRX menus load on PS3 (WaW)

The standard game-SPRX loading method (same across CoD titles):

1. **Modded EBOOT.BIN** → `/dev_hdd0/game/<TITLE_ID>/USRDIR/EBOOT.BIN` (replaces the stock EBOOT; the modded one loads the SPRX at boot). WaW title IDs: `BLUS30192` (US), `BLES00354` (EU).
2. **The `.sprx` file** → `/dev_hdd0/tmp/<name>.sprx` (must match the filename the EBOOT expects).
3. Boot the game — the menu loads with it (usually opened with a button combo like L2+R2 or D-pad).

> ⚠️ The EBOOT must match your console type: **DEX EBOOTs won't load on CEX**, and vice versa. Most SPRX releases ship DEX EBOOTs only.

**Alternative loaders (no per-game EBOOT mod needed):**

| Loader | How it works | CFW / HEN | Link |
|---|---|---|---|
| **webMAN MOD** (`/loadprx.ps3`) | Web command loads an SPRX into a slot at runtime: `http://<ps3-ip>/loadprx.ps3/dev_hdd0/tmp/menu.sprx` | CFW + HEN | https://github.com/aldostools/webMAN-MOD/wiki/Web-Commands |
| **webMAN MOD** (`boot_plugins.txt`) | VSH-level plugins auto-loaded at boot from `/dev_hdd0/boot_plugins.txt` (one path per line) | CFW + HEN | https://github.com/aldostools/webman-mod/blob/HEAD/_Projects_/load_wmm/README.md |
| **RouLette VSH Menu** (nas927/modmenups3) | VSH menu + SPRX loader + mod-menu loader + payload injector + RPC calls | CEX / DEX / HEN | https://github.com/nas927/modmenups3 |

> Note: VSH plugins (loaded via `boot_plugins.txt`) run in the XMB, **not** inside the game. Game SPRX menus need the EBOOT method or webMAN's `/loadprx.ps3` / `/gameplugin.ps3mapi` while the game is running.

### SPRX vs patch_mp.ff — WaW comparison

| | patch_mp.ff (GSC) | SPRX (native C/C++) |
|---|---|---|
| **Language** | GSC script (plaintext, compiled by game at load) | C/C++ compiled to PS3 native code |
| **What it can do** | God mode, UFO, infections, stats, gamemodes, text/UI | Everything GSC can + **aimbot, ESP, wallhack, memory hooks, anti-cheat** |
| **Install** | Replace one file via FTP | Modded EBOOT + SPRX file (2 files, region/firmware-matched) |
| **Host requirement** | Mostly host-only | Can do **off-host / non-host** features |
| **Skill to make** | Edit text, repack with CoD-FF-Tools | PS3 SDK, C++, reverse engineering |
| **CFW / HEN** | Both (just needs FTP write access) | Mostly CFW/DEX; HEN-compatible SPRX menus are rare |
| **Ban risk** | Same as any modding | Higher for aimbots/ESP (memory signatures) |
| **WaW scene share** | ~99% of menus | ParadiseWAW is essentially the only public one |

### Bottom line for WaW

- **Want a classic mod menu?** Use patch_mp.ff — it's simpler, works on CFW and HEN, and the entire WaW catalog (Purple Kush, ElitePatch, xRaW…) is GSC-based.
- **Want an aimbot or non-host features?** SPRX is the only route — ParadiseWAW is the reference implementation, but you'll need to compile it and sort out a working EBOOT for your firmware/region.
- **Want to poke memory live from your PC?** Grab an RTM tool (Project Running Fox is open source; ExIIL's is the most feature-complete for WaW) + CCAPI on the PS3.
